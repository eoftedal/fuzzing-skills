# Evidence behind the rules in SKILL.md

Not loaded with the skill. The AFL tool invocations were confirmed against the installed
AFL++ (4.33c). The rules below are marked by how they were established: **[measured]** on a
real campaign's crashes, **[tool]** from the installed tool's own output, or **[fabricated]**
with purpose-built Node packages exercising one outcome each.

Two real crash sets were replayed end to end through these scripts:

* **A stylesheet-compiler binding**: the second ASAN campaign's `crashes/` directory, 111
  ASAN crashes, with a hand-triaged answer recorded in the same workspace (4 bugs in that
  directory: 49 / 25 / 19 / 18).
* **An image-decoding binding**: an `out/plain/.../crashes` directory (37 saved by the
  campaign) plus the one input the corpus skill set aside in `crashers/` = **38**, from an
  *instrumented-only* campaign, never triaged before.

| rule in SKILL.md | how it was established |
|---|---|
| `AFL_TMIN_EXACT=1` is the RETRY after drift, not the default | **[tool]** afl-tmin 4.33c env list: "AFL_TMIN_EXACT: require execution paths to match for crashing inputs". **[measured]** as a default it rejected 97 of 112 candidates on an image-decoding binding's GIF input (0 % reduction); without it afl-tmin drifted on 1 of 6 representatives from a stylesheet-compiler binding (an over-read minimized into one in an unchecked UTF-8 decoder), which the key check caught and the EXACT retry recovered |
| both tools need `ASAN_OPTIONS` to contain `abort_on_error=1` and `symbolize=0` | **[tool]** afl-tmin 4.33c prints this requirement; set in minimize.sh, and re-run with symbolize=1 in bucket.sh to read the report |
| pass `TIMEOUT=` to afl-tmin; do not accept its default | **[tool]** `afl-tmin -h` shows `-t msec (1000 ms)`. **[measured]** 2 of the image-decoding binding's 38 crashes take 3.1 s and 3.5 s per exec against the ASAN fork harness — over tmin's default, so they would be treated as hangs and left unminimized with the failure hidden in `2>/dev/null` |
| feed afl-tmin through `/dev/stdin`, and never trust its exit code | **[measured]** with `@@` (and with `-f`) afl-tmin's temp file reached the harness EMPTY: a debug harness printed `n=0` under afl-tmin and `n=4` run directly; afl-fuzz and afl-showmap delivered the same bytes to the same binary; the forkserver reported options `0x1` (no shared-memory testcases). So tmin saw "terminates normally", minimized to 0 bytes and exited 0. Passing `/dev/stdin` as the file argument: crash mode, `Cxyz` -> `C`; a block-compression binding 7 -> 5 B, an image-decoding binding's BMP input 170 -> 57 B, a stylesheet-compiler binding's stack exhaustion 170 -> 44 B. **Correction:** an earlier version diagnosed this as broken crash detection and replaced afl-tmin with a homemade minimizer (`shrink.sh`); it is removed |
| bucket the RAW reproducers, then minimize one representative per bucket | **[measured]** a stylesheet-compiler binding's ASAN campaign, 111 crashes: screen 14 s, bucket 27 s (exactly the published 49/25/19/18), afl-tmin on 6 representatives 7 s. An image-decoding binding, whole driver including confirmation before and after minimization: 61 s; the earlier "cmin, then minimize every survivor" order ran past 20 minutes and was aborted |
| pair each campaign with the build that produced it, but LABEL with the sanitized build | **[measured]** `triage_all.sh` on the image-decoding binding's next major version (a zig build): bucketing the plain campaign against the plain harness labels everything `NO-REPORT signal-only sig6/sig11` — correct grouping, no information. Labelling with the ASAN harness instead gives a `SEGV` in a buffer reader's next-byte read (with `file:line`) and `out-of-memory in operator new[]`, with a per-input fall-back to the producing harness for any crash the sanitizer does not see (none so far in 161) |
| a campaign directory's name is not always a build directory's name | **[measured]** one stylesheet-compiler binding workspace keeps its second ASAN run in `campaign/asan2/`, and there is no `out/asan2/`: exact-name pairing silently skipped the **largest** crash set in the workspace (111 of 188 files). `harness_for` now strips trailing digits, then falls back to probing which harness reproduces most of the pool |
| strip BuildId and the harness path from the bucket key | they are build-specific and make the report table unreadable, while the function name — the part that identifies the bug — is what an unsymbolized frame still carries |
| force `symbolize=1` in bucket.sh rather than honouring the environment | **[measured]** step 1 must export `symbolize=0` (the AFL tools require it), so running steps 1 and 2 in one shell left that value in place and every bucket key degraded to `heap-buffer-overflow (harness-fork+0x152744) (BuildId: ...)` instead of a symbolized `file:line in <function>` naming the GIF decoder — still grouping correctly, but build-specific and useless in a report |
| suppress bash's own signal announcements in the screen loop | bash prints `Aborted` / `Segmentation fault` on its own stderr for every child that dies on a signal, which is one line per input in a crash-triage loop; the redirect has to belong to the compound command (`{ ...; } 2>/dev/null`), and an `if`/`||` test does not suppress it |
| start each campaign on its own build, then offer non-reproducers to the OTHER builds | **[measured]** the risk is one-directional. Cross-tabulated on both fork harnesses: a stylesheet-compiler binding's ASAN campaign (111) — both 0, ASAN-only **111**, plain-only 0; its plain campaign (13) — both 13; an image-decoding binding's plain campaign (37) — both 25, ASAN-only **2**, plain-only 0, neither 10. Not one of 161 inputs crashed the plain build alone. **Correction:** an earlier version of this skill read the image-decoding binding's "12 of 38 do not crash the ASAN harness" as crashes belonging to the plain variant; the cross-tabulation shows they reproduce on neither build — they are fork-mode non-reproducers. The real loss was the other way: the 2 ASAN-only crashes in a plain campaign, which a driver that stops at the producing build drops |
| screen the pool and print per-input rc/ms before bucketing | **[measured]** which inputs reproduce on which build, and at which ceiling, is invisible in any tool that reports only what it kept |
| default crash discovery must search the whole workspace, not `./out` | **[measured]** one stylesheet-compiler binding workspace keeps its campaigns in `campaign/`, `hunt/` and `bench/`; `find ./out -name crashes` finds **zero** of its 188 crashes |
| provenance is the build **variant**, derived from the path | **[measured]** `basename(dirname(.../afl/default/crashes))` is `default` for every campaign; on the image-decoding binding's pool it labelled 37 of 38 files `default` and the `crashers/` file `.`, losing the one field that decides which harness a crash belongs to |
| skip AFL's `README.txt` | **[measured]** the old bucket.sh filed `README.txt` as a crash and copied it to `buckets/` as the representative of a `NO-REPORT` bucket |
| check `saved_crashes` against the `id:*` count | carried over from the harness skill: two fuzzers sharing one `-o` left `fuzzer_stats` claiming 112 saved crashes over a directory of 64 files with ids 0-60 and 109-111 |
| `RETRY=` when campaign stability was below ~90 % | reproduction is not deterministic there, and a single screening run drops a crash that fires 3 times in 5; the threshold is the harness skill's measured noise floor |
| bucket on the sanitizer SUMMARY line, not the stack frames | carried over from the harness skill's `classify.sh` (since removed): a template-heavy C++ library buckets half its crashes under the return type `char` otherwise |
| collapse template arguments to a **fixpoint**, not in one pass | **[measured]** one `sed 's/<[^<>]*>/<>/g'` cannot match a template containing a template, so a stylesheet-compiler binding's single bug in a scope scanner split into two buckets (16 + 3) as `match<&Constants::brace_token.<>>` vs `match<>` (a lexer helper). Collapsing innermost-first to a fixpoint merges them into the published 19 |
| report the grouping merged on function, not the per-line split | **[measured]** a stylesheet-compiler binding, 111 crashes: the exact SUMMARY key gives 6 buckets, merging the line number gives 4 — 49 / 25 / 19 / 18, exactly the published answer. The 25-crash over-read in an unchecked UTF-8 decoder is reported at three lines of one header (`:76`, `:82` and `:84`) |
| split `NO-REPORT signal-only sigN` from `NO-CRASH (rc=N)` | **[measured]** on the image-decoding binding's pool the two classes are 10 inputs at rc=1 and 2 at rc=0, all of them "wrong variant", with no signal-only crash among them; the old single `NO-REPORT` bucket would have called all 12 persistent-mode artifacts. The signal-only class is a stylesheet-compiler binding's 13 stack exhaustions, a real DoS |
| carry `READ`/`WRITE` and size in the bucket key | **[measured]** the image-decoding binding's largest bucket (21 of 38) is a heap-buffer-overflow **WRITE** of size 1 in the BMP parser; the old key printed only `heap-buffer-overflow` and the write/read distinction — the one that changes severity — was not visible anywhere |
| a hang is a denial of service, on the bare harness or through node | there is no consumer-side mitigation for the synchronous case: a looping native call cannot be interrupted from JS (`try/catch`, `Promise.race`, `AbortController` all require the event loop, which never regains control). **[measured]** the async case costs one libuv threadpool thread per input and the pool is 4 wide — 5 concurrent `pbkdf2` calls on this host completed 4 at ~240 ms and the 5th at ~475 ms, i.e. it waited for a free thread |
| the hang path is verified end to end | **[measured]** synthetic always-looping target: 4 inputs screened to 3 real hangs (the 4th answers), bucketed by stack, minimized with `afl-tmin -H` through `/dev/stdin`, each re-checked to still hang at the full timeout. A real stylesheet-compiler binding: 8 hangs bucket by stack sampling into 2-4 groups depending on the run -- approximate, see SKILL.md |
| triage hangs too, with `afl-tmin -H` | **[tool]** `afl-tmin -h`: "-H minimize a hang (hang mode)". **[measured]** the workspaces hold more hangs than crashes in places: a stylesheet-compiler binding's plain campaign 13 crashes vs 49 hangs; a block-compression binding's plain campaign 7 vs 10 |
| verdict ladder NATIVE-CRASH > UNCAUGHT > HANG > CAUGHT > CLEAN | **[fabricated]** confirm.mjs tested with fake packages: a sync throw and a rejected Promise -> CAUGHT; an async throw and an EventEmitter 'error' with no listener -> UNCAUGHT (uncaughtException); `process.abort()` -> the shell sees sig6, NATIVE-CRASH. A signal runs no JS handler by definition |
| a timeout is HANG, not CLEAN | an input that neither returns nor errors is an algorithmic DoS through the public API; the old code reported it `CLEAN note=timeout-no-error`, i.e. "not a finding" |
| the `ALLOC_CEIL` throw is SKIPPED, not CAUGHT | the ceiling is imposed by this script, so folding it into CAUGHT ("a careful consumer is safe") is a false acquittal of our own making — the same rule as "do not manufacture a CAUGHT verdict" |
| confirm against a fresh `npm install <pkg>@<version>`, not the build tree | the question is what a user's actual binary does; a newer npm release may have fixed the bug, which is a result |
| three columns: npm install, npm JS + ASAN addon, npm JS + pristine addon | the install shows hard crashes a release build commits; the ASAN build shows memory bugs the release build hides; the pristine build answers "did your coverage instrumentation invent this?" — the harness skill builds that variant for this step and no evaluation run had ever used it. **[measured]** on an image-decoding binding both confirmed findings reproduce on pristine |
| `env -u ADDON -u LD_PRELOAD` for the install column | **[measured]** the `KEY=VALUE` argument parser exports `ADDON`, so the install column inherited it, loaded the ASAN addon with no sanitizer runtime preloaded, and reported `ERROR(rc=1)` for **every row** of the most important column. Reproduced with the documented step-3 invocation before the fix |
| hook `process.dlopen`, not the module loader, to swap the addon | **[measured]** a stylesheet-compiler binding `require()`s a binary path its own code computes, honouring the package's own environment variable for its binary path (the harness skill's JS harness for it does exactly this), which an interception on `'bindings'`/`'node-gyp-build'`/`*.node` never sees: the swap silently does not happen and the ASAN column duplicates the install column. Every addon load funnels through `process.dlopen`. **[measured]** the hook swapped an image-decoding binding's addon correctly and produced the ASAN report through the real stack |
| report `addon=swapped\|NOT-SWAPPED` and treat NOT-SWAPPED as an error | an un-swapped ADDON hides exactly the memory bugs that column exists to find, and presents as a plausible column of CLEANs |
| confirm **every** entry point the binding exposes | a stylesheet-compiler binding: 68 of 111 confirmed crashes reachable through the binding's string entry point, **25 only through its file-path entry point**, 18 through neither — the string entry point replaces invalid UTF-8 with U+FFFD before its compiler library sees a byte. A one-entry-point confirm reports those 25 as harness artifacts, which the skill then tells you to drop |
| compute `expressible`, do not assert it | the claim "every direct-only crash was explained by the byte space, not by a harness bug" is only checkable if the UTF-8/NUL round trip is computed per input; the harness skill's `real_harness.js` carried it as a `lossless=` column for the same reason |
| require `evidence=` and a `GOOD=` liveness check before believing CLEAN | an image-decoding binding's first JS harness exited 0 while decoding nothing and "confirmed" success for 18 files that had all failed, because the image object's `complete` getter it checked is hardcoded `return true` |
| do not print CLEAN for an `undefined` return | same trap: an emitter/callback arm answers through its handlers or the timeout, and a CLEAN there is the harness's own silence |
| a CLEAN minimized input is re-checked against its pre-tmin bytes | **[measured]** on an image-decoding binding the shrunk 40-byte GIF reproducer is CLEAN on the npm install while its pre-shrink original segfaults it, so the cell reads `CLEAN->NATIVE-CRASH(sig11)(orig)` — a critical finding that a naive pipeline would have dropped. The mechanism is the one predicted: shrinking happened against the sanitized harness's redzones, and the release install has none. Also **[fabricated]** earlier with a package that aborts only above 4 bytes |
| the ASAN column is authoritative only over memory the instrumented build allocated | two measured mechanisms from the harness skill's targets: an image-processing binding over system codec libraries uses the distro's JPEG and PNG codecs with no redzones; a DOM XML-parser binding's 8-byte header in front of every block its XML library allocates hid *every* under-read from ASAN (identical injected fault: mirrored allocator rc=0 silent, the library's default allocator rc=86 heap-buffer-overflow) |
| re-home the input into `Buffer.allocUnsafeSlow(len)` | `readFileSync()`/`Buffer.from()` may return a slice of node's shared 8 KiB pool, where a read past the end lands in a neighbour's bytes and ASAN sees nothing — this single line is what keeps a 1-byte over-read observable on the npm side |
| print `ulimit -s`; stack exhaustion is environment-sensitive | its threshold is the stack limit, not the input: a stylesheet-compiler binding's synchronous entry point recurses on the main thread's 8 MiB, an AsyncWorker on a libuv thread with its own stack, and the ASAN build's larger frames reach the limit at a different depth |
| name the fabricated-object and mirrored-teardown artifact patterns | an image-decoding binding: 43 of 70 crash files were phantom SIGSEGVs inside a `memset`-zeroed `std::string` member on every decode *error* path, 0 reproduced; its SVG error paths `g_object_unref` the renderer handle without nulling it, so a faithful teardown copy double-frees on fuzzer-friendly inputs |
| the allocation ceiling defaults to 1024 MB, not 4096, and the finding is the AMPLIFICATION RATIO | **[measured]** a block-compression binding, screened at 1024 MB: 10 of 10 reproduce, and the per-input ratios are `5 B -> 3,758,096,257 B (751,619,251x)`, `6 B -> 3,699,161,462 B (616,526,910x)`, `7 B -> 3,489,490,936 B (498,498,705x)`, parsed from ASAN's own `allocator is trying to allocate 0x<hex>`. 1 GB is already generous for a dependency handling a fuzz-sized input, and 4 GB sits above the entire 32-bit declared-length range, so it could not catch any bug of this class |
| walk a descending CAP_LADDER rather than picking one ceiling | a bug declaring 600 MB is invisible at 1024 MB; the default ladder `1024 256 64` stops at the first rung that reproduces, and the chosen rung is what the report must quote |
| walk the ceiling ladder PER INPUT, not until the first rung reproduces anything | **[measured]** synthetic ASAN target, pool of 3 heap over-reads + 1 input declaring 600 MB: the old ladder stopped at 1024 MB with "3 of 4" and dropped the 600 MB input with no amplification line. Per input: 3 at 1024 MB, 1 at 256 MB (`4 B in -> 629,145,600 B demanded, 157,286,400x`), each carries its own ceiling through bucketing, confirmation and minimization |
| when GOOD needs more than the first rung, walk UP | **[measured]** with a reference that legitimately allocates 1500 MB the old script died with `rep: unbound variable`; now it screens at 2048 MB, the first ceiling the reference tolerates |
| RETRY only what failed the screen | **[measured]** three deterministic duplicates, cmin kept one: the old RETRY=1 "promoted 2 intermittent crasher(s)" that had reproduced on their first run. Now it promotes 0, and genuine promotions go to `intermittent.tsv` with the attempt that hit |
| re-screen non-reproducers under the harness's MODES | **[measured]** the image-decoding binding's next major version, two EXIF-orientation JPEG seeds in `crashers/` (orientations 3 and 6): rc=0 in the default mode on both builds, rc=134 under `MODE=2`. Through `MODES="MODE=2"` they bucket as a `heap-buffer-overflow [READ-1]` in the EXIF-orientation rotation and a `memcpy` over-read of 67,634,176 bytes. Without it both were filed "does not reproduce" |
| chain each campaign's non-reproducers through the OTHER builds | **[measured]** synthetic workspace: a heap over-read saved by a *plain* campaign reproduces 0 of 1 on the plain harness and 1 of 1 when the chain offers it to the ASAN harness. On the image-decoding binding this is the 2-of-37 class |
| name a chained run after its source campaign plus the build (`plain-crashes.on-asan`) | a chained run named `<build>-<kind>` is the same directory a real campaign of that build uses, and minimize.sh wipes its OUT on start: in a workspace with both an ASAN and a plain campaign the chain would have overwritten the ASAN campaign's results |
| a harness mode needs a matching npm entry point to confirm | **[measured]** the image-decoding binding's next major version, the two bugs found under harness `MODE=2`: CLEAN through its promise-based loader, `NATIVE-CRASH(sig11)` on the npm install and `heap-buffer-overflow` on the ASAN column through an arm setting the image object's MIME data mode |
| refuse a GOOD= that does not exist | a missing reference returns the same non-zero rc at every ceiling, which the differential guard reads as "behaves the same" -- the guard silently switches off. Caught when a test passed a GOOD that existed in one workspace and not the next |
| the dlopen hook swaps per-platform optional-dependency addons | **[measured]** the image-decoding binding's next major version loads its addon from a per-platform package (`<pkg>-linux-arm64-gnu/<name>.node`), a separate npm package; the ASAN column showed `heap-buffer-overflow` (not ADDON-NOT-SWAPPED) for both of that version's confirmed findings |
| minimize hangs with a short threshold (`afl-tmin -H -t`), verify at the full timeout | **[measured]** one real 252-byte hang in a stylesheet-compiler binding: 1,458 s / 461 execs at a 10 s threshold, 238 s / 347 execs at `HANG_S=2`, same 119-byte result, still `rc=124` at 10 s. The 47 real hangs go from ~19 h to ~3 h |
| the ceiling is per input everywhere, including confirm.sh's ASAN column | confirm.sh used a fixed 4096 MB, at which a block-compression binding's 5-byte input is rc=1, so the ASAN column could acquit a declared-size bug; it now reads the ceiling each input reproduced at from `cap.tsv`. bucket.sh appends the ceiling and `allocator_may_return_null=1` last, so an inherited `ASAN_OPTIONS` cannot change the key (**[measured]**: without it, one input was labelled `allocation-size-too-big` while the screen saw it crash as a NULL dereference) |
| key an intercepted libc call by its caller, and drop the access size | **[measured]** the image-decoding binding's next major version, campaigns found through the manifest: the sanitizer reports a `memcpy` over-read at the `__asan_memcpy` interceptor, so one bug in the PNG stream reader filed as FOUR buckets (`READ-8`, `-1024`, `-8192`, `-10660`) under an unsymbolized frame. Keyed on the first project-source frame with no size it is one bucket across the asan, `asan@MODE=2`, plain `MODE=2` and `crashers` rows -- and the `-10660` one separates out as a different bug (the EXIF-orientation rotation) that the old key had hidden. The stylesheet-compiler binding still buckets to the published 49/25/19/18 |
| a manifest campaign's name already carries its mode | **[measured]** the output directory read `asan@MODE=2@MODE=2@MODE=2`: the manifest name, the override and the append each added the mode |
| report the amplification of the bytes actually shown | the block-compression binding's representative is the 5-byte minimization of a 7-byte original; the ratio computed on the original (498,498,705x) did not describe the reported bytes. bucket.sh now recomputes it per minimized input: **5 B in, 4,294,967,169 B demanded, 858,993,433x** |
| guard the ladder with a DIFFERENTIAL GOOD= check | **[measured]** requiring `rc=0` from the reference input stopped the ladder on its first rung for the wrong reason: the block-compression binding's corpus includes a deliberately invalid empty-payload seed, which is invalid by design and exits non-zero at any ceiling. Comparing GOOD's rc at the candidate ceiling against its rc with the ceiling lifted (16384 MB) is the test that actually distinguishes "the ceiling broke normal work" from "this seed was never valid" |
| retry the screen at a lower allocation ceiling before declaring a pool unreproducible | **[measured]** a block-compression binding: all 10 ASAN crashes reproduce 0 of 10 at `max_allocation_size_mb=4096` and **10 of 10** at 1024. The 5-byte input declares 2,147,221,503 bytes, so a 4 GB ceiling simply *permits* the allocation and nothing fails; a 32-bit declared length can never exceed 4 GB, so the old default acquitted every bug of this class. With the retry the pipeline collapsed the 10 crashes to **1 bug** (`out-of-memory in operator new`) and shrank it to a **5-byte** reproducer, independently rediscovering the one the campaign had found by hand |
| a `sig:09` bucket is resource exhaustion, and the install column is the one that convicts | **[measured]** a block-compression binding's workspace: all 17 saved crashes are `sig:09` (OOM-killer SIGKILL), classify reports no sanitizer finding at all, and the reproducer is 5 bytes (`d8 e5 f2 ff 0c`) declaring a huge uncompressed length — the real stack is OOM-killed after ~2 GiB or aborts on `std::bad_alloc`. `allocator_may_return_null=1`, which every step sets on purpose, makes the ASAN column read CAUGHT for it; `ALLOC_CEIL` caps `Buffer.alloc*` and cannot bound the C++-side allocation |
| cite the detection self-test when nothing is confirmed | "the campaign found no crashes" and "the harness detects nothing" produce identical output; five of six evaluation campaigns produced zero crashes, which makes this the common case rather than the edge one |

| find the ADDON path, do not assume `out/asan/Release/<name>.node` | **[measured]** across 8 build trees the addon is at `out/asan/Release/<name>.node` in the newer workspaces, flat at `out/asan/<name>.node` in the older ones, and `out/asan/lib/<name>.node` for the zig build — so the documented path is one convention among three |

What these scripts produced on every crash set in this workspace, as a check that the
pipeline works end to end (all four were run through `triage_all.sh`):

* **A stylesheet-compiler binding**, 188 crashes across three campaigns. The ASAN campaign's 111
  -> **4 bugs**, matching the published 49 / 25 / 19 / 18. The *plain* campaign's 13 -> **1
  bug**, a single `NO-REPORT signal-only sig11` bucket that the ASAN build names
  `stack-overflow`; it reduced to **19 bytes of printable ASCII** (with the since-removed `shrink.sh`; afl-tmin reaches 44 B)
  (`h,c(d(&)){f{r:&}}@m`) where the campaign's hand-reduced reproducer was 170 bytes.
* **A block-compression binding**, 10 ASAN crashes (all `sig:09`) -> **1 bug**, `out-of-memory in
  operator new`, 5-byte reproducer. Visible only at a lowered allocation ceiling.
* **The image-decoding binding's next major version (a zig build)**, 2 crashes + 4 set-aside
  crashers -> **4 bugs**: a `SEGV` in a buffer reader's next-byte read, a `READ-8` heap
  over-read via `__asan_memcpy`, `out-of-memory in operator new[]`, and the BMP parser's
  `[WRITE-1]` — the **same BMP heap write overflow as the current release**, so it is unfixed
  in the next major version's release candidate.
* **An image-decoding binding** (current release), 38 crashes -> 2 confirmed findings plus 10
  fork-mode non-reproducers and one CAUGHT: the GIF decoder (heap-buffer-overflow READ-1) and
  the BMP parser (heap-buffer-overflow **WRITE**-1). The GIF read is reported at line 685 of
  its source file for the campaign's original bytes and `:651` after shrinking — the same bug reached at a different line inside one function, which is the
  per-line split the merged grouping exists to absorb. Both
  **NATIVE-CRASH on the npm install** through its promise-based loader and through the file entry
  point. The GIF read surfaces via the `(orig)` fall-back; the BMP write reported `sig6`
  (glibc aborting on the corrupted heap) on one run and `sig11` on another — the same bug
  with a nondeterministic symptom, which is why the bucket key is the sanitizer SUMMARY and
  not the signal. Both reproduce on the pristine addon, so neither is an artifact of the
  coverage instrumentation. These were saved by an earlier evaluation run and recorded
  there as "37 saved crashes (not triaged)".

Scope: this skill decides which crashes are real and which the package already contains. It
does not build exploits. Hard crashes and memory-safety bugs in a published package are
reported to the maintainer through the package's security policy with the minimized input
and the sanitizer trace, not posted publicly ahead of a fix. The two image-decoding binding findings
above are in a currently published version and have not been reported anywhere; they are evidence
for this skill, and filing them is a separate, deliberate act.
